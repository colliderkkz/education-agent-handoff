# 学习历史删除：Web / 服务端验证

日期：2026-10-27。本轮仅本地源码、自动化与生产构建；未启动 Web 服务，未操作浏览器或模拟器，未推送或云发布。Android 设备验收和 iOS 导出由手机工程另行记录，不能由这些 Web 结果代替。

## 本轮范围

- “我的 → 小禾记住了什么 → 管理与删除历史”；报告也可带入单条证据。本人/工作区所有者可以多选已提交作答，家长、教师和教研角色无删除权限。
- 只读预览绑定 revision/digest，明确列出报告分母/答对数、知识点、旧评定、复查来源、本人关联原卷题目的会话/消息/草稿/摘要及已共享摘要数量。自由文字日志和旧规则试算的清理范围单独提示；确认使用稳定请求编号，未知结果可用原请求重试。
- 已选答案和过程真正从当前持久状态移除，报告和旧修订不取回正文；全部删除或全部无效时显示无可统计作答，不显示 0/0、零值成绩卡或表现评价。教学题库、原卷题目和未选记录保留；删除凭据只含标识和必要计数/关联信息。最小已见题族/帮助事实保留，不恢复独立新题资格。
- 照片需显式勾选。不解析旧 `paper.reason` 等自由文字来猜关联；未删记录或登记别名仍引用时保留，并在预览中说明。
- 确认后，当前浏览器当前工作区/账号的相关练习和私人会话草稿缓存清理；确认状态的可见性用于阻止延迟回调写回。旧作答、会话和纸面回传请求由领域删除凭据及提交状态阻止复活。
- 删除任务与工作区状态在同一 D1 revision CAS 中提交。图片普通 GET 与教师材料 GET 均在读取对象前后重新核对授权、登记及墓碑，因此物理回收失败也不开放旧链接。
- 存储回收只使用服务器文件索引解析的对象键，或与当前 owner 私有前缀、UUID 和服务端恢复元数据严格一致的对象键；先删对象，再删索引，最后幂等确认任务。失败保留可重试依据。每次最多处理 20 个已提交删除任务和 20 个有索引的旧代次暂存上传；可再次操作继续回收。索引缺失恢复会完整分页扫描当前归属的私有前缀，列举或元数据读取失败、分页不完整均不报告回收完成。

## 数据库迁移与上传边界

新增 `drizzle/0002_history_upload_fence.sql`，为 `uploaded_files` 增加 `history_epoch`（旧记录默认为 0），同时生成 Drizzle snapshot/journal。SQLite 实际执行迁移验证旧行保留。本轮没有对开发数据库或线上运行迁移；后续本地服务使用上传前须按顺序应用尚未应用的迁移，不能重复执行已应用的 SQL。

上传顺序仍是 **等待 R2 PUT 成功 → 登记带开始代次的服务器索引 → CAS 登记 workspace**。GC 可见的暂存索引意味着该唯一对象键的 PUT 已结束。若删除先完成，旧代次上传不能登记；补偿失败时保留索引，重试可找到。回归明确覆盖：一次 GC 在 PUT 未结束时先完成，之后 PUT 成功、旧代次登记被拒绝、补偿失败，下一次 GC 仍找到并清除该对象；不会因先删索引而漏掉晚到对象。

索引写入也失败的恢复：本轮上传会将服务端生成的 owner、uploadId 和 historyEpoch 写入 R2 自定义元数据。GC 完整分页列举当前 owner 的私有前缀，必要时通过 HEAD 读取元数据；只有 UUID 键、归属和元数据一致、代次早于已确认删除、工作区无登记或别名、无另行排程任务且无文件索引的对象才进入恢复清理。删除前再次重读工作区及权限；列举、HEAD 或分页失败会报错，不以零待办冒充全部回收。失败对象的元数据仍在，可再次识别。回归覆盖 PUT 成功 → 索引 INSERT 失败 → 补偿 DELETE 失败 → 元数据恢复清理。

仍有边界：升级前缺少恢复元数据、且没有文件索引的旧对象保留；不猜测其归属、删除代次或文件意义。同一删除代次及之后的新上传不被扫描回收。这里没有覆盖所有通用上传故障的后台修复，也没有删除其他 owner 的前缀。回收由确认后执行和用户显式重试触发，没有声称已部署后台定时 GC。

本功能不撤回已下载 PDF、系统相册原图、截图、其他应用副本或系统备份，也不宣称安全擦除 D1 历史页。未选择的图片和未明确关联的普通/题库对话不会因为文本相似而自动删除。这里只实现选中的已提交学习历史管理，不是删除整份账号或教学资料。
