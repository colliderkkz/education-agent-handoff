# 静态内容库 · 题目编写规范 v1

本规范是**静态内容库**（`content/bank/`）题目的唯一编写依据。
写完的题库必须通过 `node --experimental-strip-types scripts/validate-bank.mjs`，不通过不得合入。

---

## 1. 一次交付的形状

一次交付 = **一个教材单元**（2–4 个知识点），每个知识点 **30 道题**，共 60–120 道。

每个知识点 30 道题的构成：

| 任务类型 | 题数 | 情境数 | 情境分布 |
|---|---|---|---|
| `basic` 基础 | 10 | 3 | 4 / 3 / 3 |
| `application` 应用 | 10 | 5 | 2 / 2 / 2 / 2 / 2 |
| `transfer` 迁移 | 10 | 10 | 每情境 1 道 |

**为什么这样配**：五星门槛一次就要消耗 10 个互不相同的题族（讲解 1 + 提示 1 + 基础 3 + 应用 3 + 迁移 2）。
迁移题是唯一会**永久耗尽**的池子（间隔复查要求「全历史未见」），所以给足 10 个 = 5 轮复查。

## 2. 输出格式

写入 `content/bank/batch-<unitId>.json`，是一个**题目数组**。每道题：

```json
{
  "id": "bank-math-1-place-001",
  "familyId": "math-1-place__fam-01",
  "version": 1,
  "text": "一个数最高位是千万位，这个数最小是多少？",
  "answer": "10000000",
  "unit": "万",
  "knowledgeId": "math-1-place",
  "difficulty": "基础",
  "source": "小禾教研原创静态题库 · 样例编写",
  "sourceScope": "小学四年级上册静态内容库 · 未人工逐题复核 · 教学有效性待教研验证",
  "steps": ["最高位是千万位，最小的数就是 1 后面跟 7 个 0。", "10000000。", "答：10000000万。"],
  "hint": "先想清楚数位顺序：个位、十位、百位、千位、万位、十万位、百万位、千万位。",
  "alternative": "也可以从 1000 万这个说法去想：1000 万 = 10000000。",
  "prerequisites": ["math-1-place"],
  "status": "published",
  "authorId": "bank-author-math",
  "reviewerId": "bank-check-math",
  "reviewNote": "题库由教研模板批量编写并通过自动校验脚本；未经逐题人工复核，不代表教学有效性已验证。",
  "createdAt": "2026-11-01T00:00:00.000Z",
  "taskType": "basic",
  "contextId": "math-1-place__place-order",
  "image": "/illustrations/math/math-1-place/place-value-chart.svg"
}
```

### 字段硬约束

| 字段 | 规则 |
|---|---|
| `id` | `bank-<knowledgeId>-<3 位序号>`，全库唯一，只允许 `A-Za-z0-9_.:-` |
| `familyId` | `<knowledgeId>__fam-<3 位序号>`，**一题一族**（30 题 = 30 族） |
| `contextId` | `<knowledgeId>__<ascii-kebab>`，≤100 字符 |
| `taskType` / `contextId` | **同时存在或同时缺省**，不能只写一个 |
| `answer` | 数学题为纯数值（可含小数）；语文/英语开放题为短语或句子 |
| `unit` | 与答案单位一致；开放题留空字符串 |
| `steps` | 至少 1 条，每条 ≤1500 字，**必须有一条含「答：」** |
| `hint` | 非空，是**引导**不是答案 |
| `alternative` | 非空，必须是**另一种解法**，不能与 `steps[0]` 字面相同 |
| `prerequisites` | 非空数组，每项必须是教材目录里的知识点 id |
| `authorId` / `reviewerId` | 必须是**两个不同的值**（审核人分离） |
| `status` | 固定 `published` |
| `source` / `sourceScope` / `reviewNote` | 用上面的模板原文，不要改写 |

## 3. 数学题的算术要求（校验脚本会逐题验算）

1. **解题步骤里要有一条真正算出答案的等式**：左边是一个算术表达式，右边是结果数字。
   这条等式**不必是 `steps[0]`** —— 有些题第一步是列式，真正的算式在第二、三步。
   运算符支持 `+ - × ÷`，也支持数学符号 `− × ÷`。**支持括号**与一元负号，所以两步算式可以直接写：
   - ✅ `"624 ÷ 26 = 24。"`
   - ✅ `"(12 + 8) × 2 = 40。"`（周长这类需要两步的题）
   - ✅ `"300 − 200 = 100。"`
   - ✅ `"-5 + 5 = 0。"`（负数结果也认）
   - ❌ `"先算 624 除以 26。"`（不是等式，无法验算）
   - ❌ `"624 ÷ 26 = 24 元"`（等号右边不能带单位）
2. **不许凑式**。算出 `answer` 的那条等式如果是「加上或减去 0 得到原数」（`5 + 0 = 5`、`12 − 0 = 12`），
   判定为**没有实际计算**，校验不通过，必须重写解题步骤。
   原因是凑式会让脚本以为这题验算过了，其实一步也没算。
3. 等号左边**第一个数字**最好出现在 `text` 里（它是题目的核心数）；出现在中间步骤里也只记提示。
   其余操作数可以是换算常数（`÷ 10000`）或中间量（`300 − 200` 里的 200）。
4. 等式结果必须等于 `answer`
5. `answer` 必须能被 `lib/grading.ts` 的 `gradeAnswer` 判为正确，且 `answer + 1` 必须判为错误
6. `unit`（若非空）必须出现在 `text` 或某一步 `steps` 里

**如果某个求法确实无法用等式表达**（例如「量角器读数」「四舍五入取近似数」「判断是不是垂直」「靠韦达定理直接得参数」），
把这一步写成一句**答题要点**即可，校验脚本会记一条提示让人工确认。**但不要为了让脚本通过而把题目问法改得别扭** ——
例如几何周长题现在可以用 `(12 + 8) × 2 = 40` 直接问周长，不需要退而求其次问「半周长」；
反过来也**不要为了让脚本通过而在首步硬凑一个等式**。

## 4. 两条内容寻址硬约束（不遵守则整个库导不出内容包）

这两条来自 `lib/server/content.ts`，是系统的既有规则，不是本次新增：

1. **规范化题干全库唯一**
   规则：`text` 做 NFKC 规范化 → 转小写 → 去掉所有空白后，全库不得有两道题相同。
   ⇒ **不能出一道题后换个数字再出一道**。

2. **数字同形必须同题族**
   规则：把 `text` 规范化后把数字全部替换成 `#`，若两道题得到同一个形状，**必须归入同一 `familyId`**。
   ⇒ 「同一情境、只换数字」**不算新题族**。

   **推论（最重要的一条）**：一题一族的真正含义是 —— **一道题只能有一个数字模板**。
   30 道题就是 30 个不同的「题型模板」，不能是 12 个模板各换几次数字。

   写题时请先列一张**模板清单**：这道题考什么？换成另一个数字还是同一个模板吗？
   如果只是换数字，请换**情境**（不同的人、不同的东西、不同的问法），而不只是换数字。

## 5. 情境（contextId）怎么设计

情境 = 「换一个问法这件事」的标识。同一个知识点下的 30 道题，应当覆盖**至少 18 个不同情境**。

- 基础题 3 个情境：如 `place-order`（数位顺序）、`read-by-groups`（按万级个级读）、`zero-placeholder`（中间末尾的 0）
- 应用题 5 个情境：如 `count-in-groups`（按组计数）、`school-supplies`（学校物资）、`distance`（路程）
- 迁移题 10 个情境：每题一个全新情境

情境 id 用英文 kebab-case，语义清楚，能看出「这组题在考什么」。

## 6. 语文 / 英语开放题

开放题没有数值答案，`answer` 写**参考答案要点**（一句话或短语），`unit` 留空字符串。

- `steps[0]` 不需要是等式，但要写成**答题要点**而不是复述题干
- `alternative` 写**另一种答题角度或表达方式**
- `hint` 引导思考方向，不给答案
- 同样受「题干全库唯一」「数字同形同族」两条约束

## 7. 配图

只有**图形真的需要看图才能做**的题目才配图（几何图形、统计图、方格纸、数轴等）。
纯计算题不要配图。

配图规格写在 `content/bank/figures.json`，由 `node scripts/generate-illustrations.mjs` 生成 SVG 到
`public/illustrations/<subject>/<pointId>/<slug>.svg`。题目的 `image` 字段写**不带 hash 的稳定路径**。

约束：
- **图形内部只允许 ASCII 数字与几何符号，绝不出现中文** —— SVG 转 PNG 走 librsvg，没有中文字体的机器会把中文渲染成方块
- 边长、角度等数字直接标在图上（`"8"`、`"60°"`）
- 图例、轴标题等中文说明放在页面层，不烧进图片
- **写了 `image` 就必须真的有那个文件** —— 校验脚本会逐个检查 `public/illustrations/...` 下有没有对应的 SVG
- **题干提到「如图 / 图中 / 下图」就必须配图** —— 反过来也成立：没有图就别写「如图」。
  学生会照着题干去找图，找不到就是缺陷；这类题要么补图，要么把条件写进题干

## 8. 交付前自检

写完先跑：

```sh
node --experimental-strip-types scripts/validate-bank.mjs
```

必须 0 problems。校验脚本会检查：题量与配比、id/题族唯一、题干规范化唯一、数字同形同族、
题族数 ≥24、情境数与任务类型联动、答案判分与算术验算（含凑式检测）、步骤/提示/另一解法、
前置知识引用、语义近似查重、字段长度与枚举、配图文件存在与「如图」配图一致、免责措辞、
**以及按学科切包后走生产代码 `parseContentPackage` 的端到端校验**。

有问题就按错误信息逐条改，**不要绕过**。

## 9. 文风基准

参考仓库里已有的原创内容：

- 教材知识点解释：`lib/curriculum-explanations.ts`（每个知识点一段原创说明，面向四年级学生）
- 导读题：`lib/curriculum-practice.ts`（57 道原创自练题，含参考解答）
- 演示题库：`lib/seed.ts`（30 道已发布演示题的写法与深度）

要求：面向四年级学生、原创、不照抄教材原文、题干保留必要条件与单位、不使用超纲表述。
